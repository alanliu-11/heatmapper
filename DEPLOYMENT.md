Deployment guide — Render (recommended)

This repo contains a FastAPI app (`app.py`) and a static frontend in `static/`.

Quick summary
- Frontend: can be deployed to Vercel as a static site (deploy `static/`).
- Full app (recommended): deploy to Render, Fly.io, Railway, or similar that supports long-lived Python services + Postgres.

Render instructions (Docker or native):

1. In the Render dashboard, create a new Web Service from this GitHub repository.

2. The repo contains a `render.yaml` manifest and a `Dockerfile`. You can deploy
   either using the Docker image (recommended for parity with local runs) or
   using Render's native Python runtime.

   - Docker (recommended): Render will build the provided `Dockerfile`.
     The container exposes port 8000 and the image installs `requirements.txt`.
   - Native Python: `render.yaml` is configured to run `pip install -r requirements.txt`
     and start `uvicorn app:app --host 0.0.0.0 --port $PORT`.

   Note: `requirements.txt` now includes `yfinance` so options chains are fetched
   from Yahoo by default (no API key required). For production stability you may
   choose to integrate a paid provider (Tradier, Polygon, etc.) and add its
   keys as env vars in the dashboard.

3. Create or attach a Postgres addon (or set `DATABASE_URL` to your managed DB connection string).
   Use a pooled connection string if your provider offers one.

4. Set required environment variables in the Render dashboard (values marked
   `sync: false` or `generateValue` are treated as secrets in the manifest):

   - `DATABASE_URL` (required)
   - `SECRET_KEY` (JWT signing key; can be generated by Render or provided)
   - `VAPID_PRIVATE_KEY` and `VAPID_PUBLIC_KEY` (optional — generate below)
   - `BRIGHTDATA_USER`, `BRIGHTDATA_PASS`, `BRIGHTDATA_API_TOKEN` (optional — set if you want Bright Data scraping)

   The app uses `yfinance` (Yahoo) by default for options chains and requires no
   provider account for basic usage. If you prefer a paid data source, set the
   corresponding provider keys in the dashboard and update `scraper.py` or add
   a provider adapter.

Generating VAPID keys

Run locally or in a scratch container and copy the values into the dashboard:

```bash
python -c "from py_vapid import Vapid; v=Vapid(); v.generate_keys(); print('private:', v.private_pem()); print('public:', v.public_key())"
```

Note on background scanning
- Render's free web service spins down after ~15 minutes of inactivity, so the
   first request after idle is slow (~30s cold start) and the in-process
   background scanner pauses while asleep. The app's background scanner runs
   every 15 minutes when the service is active; expect similar delays on other
   free hosting tiers.

Docker

- A `Dockerfile` is included. Render will build the image automatically when you
   deploy the repo. Locally you can build and run the image for testing:

```bash
docker build -t heatmapper:local .
docker run -e DATABASE_URL="postgres://user:pass@host:5432/db" -p 8000:8000 heatmapper:local
```

Local quickstart (without Docker)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload
# open http://127.0.0.1:8000
```

Notes
- The app requires a Postgres DB. On first startup the schema is created automatically.
- Keep secrets out of source control; use the platform's secret env var features.
